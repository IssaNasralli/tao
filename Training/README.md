# TAO-Net: Model Training

This directory contains the training pipeline for TAO-Net, a multimodal pedestrian forecasting model that combines visual appearance, human pose, orientation, and observed bounding-box trajectories.

The training process is implemented primarily in `cross_val.py`, `csv_features.py`, and `ato.py`. It trains a model for **future pedestrian bounding-box prediction and pedestrian action classification** using preprocessed JAAD data.

## 1. Prepare the Training Data

The training pipeline uses the five CSV files generated by the preprocessing stage:

| File | Description |
|---|---|
| `features.csv` | Visual appearance feature vectors |
| `pose.csv` | Human pose landmark coordinates |
| `angle.csv` | Pedestrian orientation angles |
| `x_traject.csv` | Observed pedestrian bounding boxes |
| `y_traject.csv` | Future pedestrian bounding-box trajectories |

For the default JAAD configuration, the expected paths are:

```text
data45_jaad/
├── features.csv
├── pose.csv
├── angle.csv
├── x_traject.csv
└── y_traject.csv
```

These paths are relative to the current working directory. The training script must be run from a directory where `data45_jaad/` is accessible, or the paths in `cross_val.py` must be updated.

The prepared dataset is available in `Preprocessing/data45_jaad.zip`. Extract the archive and configure the training paths before starting.

For instructions on generating these files from raw JAAD videos and annotations, see [`../Preprocessing/README.md`](../Preprocessing/README.md).

## 2. Data Loading and Preprocessing

The `csv_features.py` module loads the CSV files and prepares the arrays consumed by the model.

The main function is:

```python
load_and_preprocess_data(
    feature_path,
    angle_path,
    pose_path,
    x_traject_path,
    y_traject_path,
    feature_max,
    angle_max,
    frame_width,
    frame_height,
    sequence_length=16
)
```

The function performs the following operations:

1. Loads the five CSV files using pandas.
2. Checks that all five files contain the same number of rows.
3. Extracts the action labels from the last column of `features.csv`.
4. Removes the final column from each data array.
5. Reshapes the data into the expected sequence dimensions.
6. Returns the multimodal input arrays, future trajectory targets, and action labels.

### Expected tensor shapes

For the default configuration, each sample is represented as follows:

| Input or target | Shape per sample | Description |
|---|---|---|
| Appearance features | `(15, 32)` | 15 frames with 32 features per frame |
| Pose | `(15, 24)` | 15 frames with 24 pose values per frame |
| Orientation | `(15, 1)` | One orientation value per observed frame |
| Observed bounding boxes | `(15, 4)` | Four coordinates per observed frame |
| Future bounding boxes | `(45, 4)` | Four coordinates per future frame |
| Action label | Scalar | Pedestrian action class |

The model uses four inputs: appearance, pose, orientation, and observed bounding boxes. Its two outputs are future bounding-box predictions and pedestrian action probabilities.

**Data consistency:** All five CSV files must contain corresponding samples in the same row order. The loader checks that the row counts match, but it does not verify sample identity or alignment across files.

### Important implementation detail

Although `csv_features.py` defines normalization and denormalization helper functions, `load_and_preprocess_data()` does not currently apply them. The coordinate normalization described in the helper functions should not be assumed to occur automatically during training.

The supplied model configuration also assumes a fixed observation length of 15 frames and a prediction horizon of 45 frames.

## 3. Model Architecture

The model is defined in `ato.py` and constructed using TensorFlow Keras.

It combines multimodal encoders with a trajectory decoder and an action classification branch.

### Input modalities

- **Appearance encoder:** Uses multi-head self-attention followed by an LSTM to encode visual features.
- **Pose encoder:** Uses multi-head self-attention and an LSTM, initialized using the appearance encoder's hidden state.
- **Orientation encoder:** Uses multi-head self-attention followed by an LSTM.
- **Bounding-box encoder:** Encodes the observed pedestrian bounding-box sequence.

### Multimodal fusion

The hidden and cell states from the pose and orientation encoders are combined to create contextual representations. Attention layers are then used to construct the context passed to the trajectory prediction branch.

The model also predicts pedestrian actions using the pose encoder representation.

### FiLM modulation

The predicted action probabilities are used to generate feature-wise linear modulation parameters for the observed bounding-box sequence. This allows the action classification branch to influence the trajectory forecasting branch.

### Output heads

The model produces two outputs:

1. **`bbox_output`:** Predicts 45 future bounding boxes, each represented by four coordinates.
2. **`pedestrian_classification`:** Predicts probabilities for two pedestrian action classes, corresponding to Standing and Walking as encoded by the dataset.

### Loss functions

The model is compiled with the Adam optimizer and two loss functions:

| Output | Loss | Weight |
|---|---|---|
| `bbox_output` | Mean squared error (MSE) | `1.0` |
| `pedestrian_classification` | Sparse categorical cross-entropy | Configurable |

The action classification loss weight is controlled by the `loss_weight` hyperparameter. This parameter determines the relative contribution of the classification loss to the total training objective.

## 4. Configure Training

The main training script is `cross_val.py`.

The following parameters are configured in the script:

```python
seed = 42
sequence_length = 45
dataset = "jaad"

feature_max = 6.0
angle_max = 180
frame_width = 1920.0
frame_height = 1080.0

epochs = 1000
```

The random seed is used to initialize TensorFlow, NumPy, and Python's random number generator.

The script searches combinations of the following hyperparameters:

```python
unit_lstm_values = [1024, 512, 256, 128, 64]

batch_size_values = [
    512, 256, 192, 160, 96, 128, 64
]

loss_weight = [
    1000, 900, 800, 700, 600, 500,
    400, 300, 200, 100, 1
]
```

The training process iterates over the Cartesian product of these lists, skipping combinations recorded in the training results file.

This configuration defines **385 possible hyperparameter combinations**.

Each combination specifies:

- Number of LSTM units.
- Batch size.
- Classification loss weight.

The search may require substantial computational resources, especially for configurations with large LSTM layers, large batches, and many epochs.

To conduct a smaller experiment, reduce the values in the hyperparameter lists before starting training.

## 5. Run Training

From the `Training/` directory, execute:

```bash
python cross_val.py
```

Before running, verify that:

1. All required Python modules are available.
2. The five CSV files exist at the paths configured in `cross_val.py`.
3. The output directory for training results exists.
4. Sufficient system memory and GPU memory, if using a GPU, are available.

The training script loads and preprocesses the data, iterates over the hyperparameter combinations, builds a new model for each combination, and calls `ato.train_model()`.

The model uses early stopping and model checkpointing to monitor validation loss during training.

### Data splitting

The current implementation splits the samples into three subsets:

| Subset | Approximate proportion |
|---|---:|
| Training | 50% |
| Validation | 10% |
| Testing | 40% |

The first split reserves 40% of the data for testing. The remaining 60% is then split into training and validation subsets.

The same `random_state` is used for the splits across hyperparameter combinations.

**Evaluation note:** The script evaluates the model on the test subset inside `train_model()` for every hyperparameter combination. If the test results are used to select hyperparameters, the test set is no longer an untouched final evaluation set. For rigorous experimentation, use validation results for model selection and reserve the test set for the final evaluation.

The current implementation uses a random sample-level split. If multiple samples originate from the same video or pedestrian track, a grouped split may be preferable to reduce potential data leakage.

## 6. Training Results and Checkpoints

### Training history

The script reads previous experiment configurations from:

```text
training_history_45/training_results_jaad.txt
```

It records the following fields:

```text
LSTM_units, batch_size, weight, loss,
loss_bbox_output, loss_pedestrian_classification
```

The exact header should match the format expected by `training_history.read_training_results()`.

After each experiment, the script appends the final total loss, bounding-box loss, and classification loss to the results file.

The file is flushed after each result so that completed experiment records are written to disk promptly.

### Model weights

During training, the best checkpoint is saved using a filename based on the prediction horizon, number of LSTM units, and dataset:

```text
45frames_unit_<units>_jaad.h5
```

The final weights are also saved using a filename containing the hyperparameters:

```text
45frames_unit_<units>_batch_<batch_size>_loss_<loss_weight>_jaad.h5
```

The exact filenames are generated by `ato.py`.

### Model architecture

The script exports the model architecture to:

```text
model_architecture.json
```

Because this filename is reused across experiments, it is overwritten by subsequent model configurations. Save a separate architecture file per experiment if you need to preserve all configurations.

### Training plots

The script calls `training_history.plot_and_save_history()` to plot and save the training history.

The output location and naming convention depend on the implementation of `training_history.py`.

## 7. Resuming Experiments

The training script reads the existing results file and skips hyperparameter combinations that have already been recorded.

This allows the search to continue without repeating completed combinations.

For example, if a combination of LSTM units, batch size, and classification loss weight is already listed in `training_results_jaad.txt`, the script skips that combination.

**Important:** The results file is an experiment log, not a complete training-state checkpoint. Resuming the search does not automatically restore the optimizer state or the exact point of an interrupted training run. The weight-loading behavior in `ato.py` must also be considered when restarting an experiment.

## 8. Troubleshooting

### CSV files cannot be found

Check the working directory and verify that the paths in `cross_val.py` point to the extracted dataset.

### Mismatched CSV row counts

All five CSV files must have the same number of rows. Regenerate or repair the dataset if samples are missing from any modality.

### Reshape errors

Verify that the CSV columns match the expected dimensions:

- 15 frames × 32 appearance features.
- 15 frames × 24 pose values.
- 15 orientation values.
- 15 observed bounding boxes × 4 coordinates.
- 45 future bounding boxes × 4 coordinates.

The loader removes the final column from each file before reshaping, so each CSV must include the additional final column expected by the implementation.

### Out-of-memory errors

Reduce the batch size, decrease the number of LSTM units, or run a smaller hyperparameter search.

### Experiments are skipped unexpectedly

Inspect `training_results_jaad.txt` and verify the recorded hyperparameter combinations.

### Checkpoint loading issues

Review the weight filenames generated in `ato.py`. The initial checkpoint filename does not include the batch size or classification loss weight, whereas the final filename does. Ensure that the intended checkpoint is being loaded for each experiment.

These improvements will help ensure that results are easier to reproduce, compare, and interpret across training runs and future ablation studies.
